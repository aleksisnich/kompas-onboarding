# Компас 🧭 — адаптация без стресса

«Компас» — демонстрационное веб-приложение для адаптации новичков торговой компании: база знаний по ролям, ответы на вопросы, опросы в первые 90 дней, обращения в панель HR и статус решения. Вся информация о сотрудниках и все инструкции **вымышлены**.

## Запуск у себя (Windows)

1. Распакуйте архив и откройте папку `kompas`.
2. Двойной щелчок по `START_WINDOWS.bat`, либо откройте PowerShell в папке и выполните `py server.py`.
3. Откройте **http://127.0.0.1:8000** и не закрывайте окно запущенного Python.

Нужен Python 3.10+, внешних библиотек нет. Файл `.env.example` — лишь образец настроек: сервер не загружает его автоматически. Локально изменения в демо сохраняются в `demo_state.json` (файл исключён из Git).

## Публикация на Render — чтобы работодатель просто открыл ссылку

**Никакие ключи для первого развёртывания не нужны.** Без них чат честно показывает ответы из учебной базы знаний и отмечает режим «поиск по базе». Код не должен содержать личных API-ключей.

1. Создайте **новый GitHub-репозиторий** (например, `kompas-onboarding`). Загрузите **содержимое** папки `kompas` в корень репозитория: `server.py`, `render.yaml`, `knowledge.json`, папку `static` и другие файлы должны оказаться рядом.
2. Откройте https://dashboard.render.com/ и авторизуйтесь через GitHub.
3. Самый простой вариант: **New → Blueprint**, выберите свой репозиторий. Render прочитает готовый `render.yaml`. Убедитесь, что выбрана **Free**-конфигурация, и примените изменения.
4. Альтернатива: **New → Web Service → GitHub repository**, Python, Free. В поле **Build Command** введите `python -m compileall -q .`; в **Start Command** — `python server.py`. В **Environment** добавьте `DEMO_PUBLIC=1`, `ENABLE_LLM=0`. В **Health Check Path** укажите `/api/health`.
5. Дождитесь статуса **Live** и откройте выданную Render ссылку вида `https://...onrender.com` (реальный адрес создаст сам Render).
6. Проверьте: главная → база знаний → чат → обращение → панель HR → закрытие обращения. Откройте сайт в режиме инкогнито и убедитесь, что там **отдельное** демо-состояние.

Render Free может выключать простаивающий сервис и терять его временные данные при перезапуске. Первый визит после простоя может загружаться дольше. Это нормально для прототипа, но **не** подходит для реальных кадровых данных. Для постоянного хранения понадобится база данных и авторизация.

## Как устроены данные в опубликованной версии

- `DEMO_PUBLIC=1`: каждый браузер получает случайную cookie-сессию, а демонстрационные обращения и чек-листы хранятся **отдельно в памяти сервера**. При перезапуске они сбрасываются. Посетитель может самостоятельно пройти полный сценарий без влияния на другие браузеры.
- В этом демо можно переключаться между вымышленными сотрудниками и HR без пароля; это **не настоящая система разграничения доступа**.
- `DEMO_PUBLIC=0` (по умолчанию): локальная версия использует файл `demo_state.json`.
- Ключи, вопросы и переписка в интерфейсе не включены в ZIP. Текст введённого в чат вопроса не сохраняется на сервере, но при включении внешней модели отправляется провайдеру API.

## Генеративный ИИ (опционально, сейчас выключен)

Приложение **без ключа полностью работоспособно** в режиме локального поиска по 10 демонстрационным инструкциям. Для включения внешней модели позже задайте **только в приватных настройках Render Environment**:

- `ENABLE_LLM=1`
- `OPENAI_API_KEY` — секретный ключ, никогда не сохраняйте его в репозитории, исходниках, `.env.example` или скриншотах
- `OPENAI_MODEL=gpt-4.1-mini` — необязательное имя модели

Внешняя модель получает только найденные учебные материалы и вопрос. Если не удалось получить ответ, приложение возвращается к обычному поиску. Для публичного демо есть простые ограничения запросов (до 8 обращений к LLM на сессию, до 60 за время работы процесса), **но они не являются гарантией от злоупотреблений**: обязательно включайте бюджетные лимиты у провайдера либо оставляйте ИИ выключенным. Платные запросы могут расходовать средства владельца ключа.

## Проверка

Запустите из папки проекта:

```bash
python -m unittest discover -s tests -v
```

Проверьте вручную: для продавца спросите о возврате товара; для сотрудника склада тот же вопрос должен дать предупреждение о несовпадении должности. Затем отправьте запрос помощи и проверьте создание и закрытие обращения в HR-панели.

## Ограничения

- Нет интеграции с Битрикс24, настоящих регламентов, авторизации и разграничения прав.
- Нет автоматических рассылок и планировщика опросов.
- Нельзя делать выводы о снижении текучести кадров без испытания на реальных данных.
- В публичном демо не вводите настоящие персональные данные, пароли и сведения о покупателях.

**Зачем это сделали:** вместо необоснованного прогнозирования увольнений предлагается помочь сотруднику быстро найти инструкцию и безопасно запросить поддержку, а HR — не потерять обращение.
